# نظام عيادة أوراس لطب الأسنان

تطبيق Electron عربي لجهاز واحد على Windows لإدارة المرضى والزيارات والمواعيد والخطط العلاجية والمصروفات والمخزون والمعامل والتقارير. المشروع هنا يشمل واجهة `index.html` وملفات Electron ومكتبات Excel وPDF المحلية في `vendor/`، فلا تحتاج إلى استبدال HTML يدوياً داخل مشروع آخر. لا يوجد خادم منفصل ولا مزامنة بين الأجهزة.

> **قبل استخدام بيانات مرضى حقيقية:** التشفير يحمي ملف قاعدة البيانات عند إغلاق التطبيق، لكنه لا يحل محل تأمين Windows والنسخ الاحتياطية أو مراجعة أمنية مناسبة للبيانات الصحية. صلاحيات الأدوار في الواجهة وحدها ليست مصادقة أمنية موثوقة.

## إعداد المشروع وبناء نسخة Windows

1. على جهاز Windows ‏x64، ثبّت Node.js ‏22.17 أو أحدث ضمن الإصدار 22، أو الإصدار 24 فأحدث. احفظ **المشروع كاملاً** في مجلد واحد، بما في ذلك `main.js` و`preload.js` و`secure-database.js` و`key-vault.js` و`unlock.html` و`unlock.js` و`index.html` و`vendor/` و`package.json` و`package-lock.json` و`.npmrc` و`scripts/`. لا تنقل `index.html` وحده إلى مشروع Electron القديم.
2. إذا أردت شعارك في التطبيق، ضع ملفك السابق باسم `icon.ico` في جذر المشروع. عدم وجوده لا يمنع البناء؛ سيُستخدم شعار Electron الافتراضي.
3. افتح PowerShell داخل مجلد المشروع، ثم نفّذ:

   ```powershell
   npm ci --ignore-scripts
   npm start
   ```

   يتطلب التثبيت الأول اتصالاً بالإنترنت لتنزيل الاعتمادات وElectron. يُعطّل `npm ci --ignore-scripts` خطوات التثبيت التلقائية لتجنّب إعادة بناء المكتبة الأصلية؛ ينزّل `npm start` ملف Electron الرسمي عند تشغيله أول مرة. بعد التثبيت يعمل نظام العيادة محلياً؛ فتح واتساب يحتاج اتصالاً بالإنترنت.
4. بعد تجربة التطبيق، أنشئ نسخة Windows بالأمر نفسه الذي اعتدت عليه:

   ```powershell
   npm run build
   ```

   الناتج داخل `dist/OrasDentalClinic-win32-x64/`. شغّل `OrasDentalClinic.exe` **مع الاحتفاظ بالمجلد الناتج كاملاً**؛ ملف EXE وحده لا يحتوي على كل ملفات Electron والواجهة. الناتج مجلد تطبيق وليس ملف تثبيت. قد يعرض Windows تحذيراً لأن التطبيق غير موقّع.
5. للتحديثات اللاحقة، حدّث ملفات هذا المشروع الموحّد ثم شغّل `npm ci --ignore-scripts` إذا تغيّرت الاعتمادات و`npm run build`. يحزم الأمر الواجهة ومجلد `vendor/` تلقائياً، ولا يحزم ملفات النسخ الاحتياطية الموجودة في جذر المشروع. يُستبدل مجلد الناتج القديم داخل `dist/` عند البناء؛ لا تحفظ نسخك الاحتياطية فيه. قاعدة بيانات العيادة تبقى خارج مجلد البناء.

تستخدم هذه النسخة Electron أحدث من المشروع القديم، وتُبقي اسم الحزمة `oras-dental-clinic` للحد من تغيّر مجلد بيانات التطبيق. تُرفَق مكتبة قاعدة البيانات بملف Windows x64 أصلي من نوع N-API؛ لا يتطلب إعداد المشروع المعتاد خادماً أو Python.

## فتح قاعدة البيانات

- في أول تشغيل اختر **عبارة تشفير** قوية من 12 حرفاً على الأقل وأكّدها. إذا كانت لديك قاعدة بيانات من الإصدار السابق، فأدخل عبارتها الأصلية مرة واحدة بعد التحديث. يحفظ Windows العبارة محمية باستخدام DPAPI لهذا الحساب والجهاز، ثم يفتح البرنامج القاعدة تلقائياً في المرات التالية. تبقى كلمات مرور المدير والموظفين مستقلة كما هي.
- احتفظ بعبارة التشفير في مكان آمن ومنفصل عن النسخ الاحتياطية، حتى لو لم تعد تدخلها عند التشغيل. قد تحتاجها عند تغيير جهاز أو حساب Windows، أو تلف ملف المفتاح المحمي أو استعادة نسخة بعبارة أخرى. إذا فقدت العبارة **ولم يعد المفتاح المحمي وحساب Windows متاحين** فلا يمكن فتح قاعدة البيانات أو نسخها المشفّرة؛ لا توجد كلمة استرداد عامة. يمكن استيراد نسخة JSON قديمة بشكل منفصل إن وُجدت.
- يخزّن التطبيق المفتاح المحمي في `%APPDATA%\oras-dental-clinic\clinic-data\oras-dental-key.dpapi`، وليس كنص صريح. حماية DPAPI مرتبطة عادةً بحساب Windows والجهاز ولا تضمن إمكانية فتح الملف بعد تغيير الحساب أو استعادة النظام. ملف `.orasdb` وحده لا يتضمن مفتاح DPAPI. إذا تعذّر حفظ المفتاح، يُظهر التطبيق تحذيراً وقد يطلب العبارة عند التشغيل القادم؛ ولا يتحول إلى تخزين غير مشفّر.
- ملف البيانات في المسار المعتاد:

  ```text
  %APPDATA%\oras-dental-clinic\clinic-data\oras-dental.sqlite3
  ```

  خزّن البيانات وعبارة التشفير على الجهاز الذي يستخدمه النظام. لا تضع قاعدة البيانات في مجلد مشترك أو متزامن أثناء تشغيل التطبيق. يُسمح بتشغيل نسخة واحدة من التطبيق الجديد في الوقت نفسه.
- يستخدم التطبيق `SQLite3MultipleCiphers` عبر `better-sqlite3-multiple-ciphers` بوضع متوافق مع SQLCipher 4. المجموعات الحالية محفوظة كقيم JSON داخل قاعدة SQLite المشفّرة، مع معاملات ذرّية للحفظ والاستعادة. يجب فتح قاعدة البيانات بعبارة التشفير قبل قراءة البيانات؛ SQLite العادي لا يفتح الملف. المكتبة ليست مكتبة SQLCipher نفسها، وقد تختلف أدوات عرض قواعد البيانات في التوافق.
- إذا تعذّر الفتح، تحقّق من العبارة والنسخة الاحتياطية ومساحة القرص والصلاحيات. قد تعني الرسالة أيضاً تلف الملف. التطبيق لا يُنشئ قاعدة فارغة بدلاً من الملف الموجود تلقائياً.

### كلمات مرور الأدوار

عند إنشاء قاعدة جديدة **من دون بيانات منقولة**، كلمات الدخول الافتراضية هي:

| الدور | كلمة المرور |
|---|---|
| المدير | `manager2026` |
| الموظف الصباحي | `morning2026` |
| الموظف المسائي | `evening2026` |

غيّرها من الإعدادات بعد الدخول. كلمات المرور الجديدة تُخزَّن كبصمات PBKDF2 مع ملح عشوائي داخل قاعدة البيانات المشفّرة؛ الكلمات القديمة التي كانت محفوظة تبقى صالحة حتى تغييرها. عند نقل التخزين القديم تُنسخ مفاتيح كلمات مرور الأدوار الثلاثة المتاحة أيضاً. إذا كانت النسخة القديمة تستخدم كلمة ثانية مستقلة لفتح «وضع المدير»، فالنسخة الجديدة تعتمد كلمة **دور المدير** بدلاً منها. هذه الأدوار تنظّم الواجهة فقط ويمكن تجاوزها ممن يستطيع تعديل التطبيق أو استخدام أدوات المطور؛ عبارة التشفير هي حماية الملف عند الراحة، وليست نظام صلاحيات مستقل.

## الانتقال من نسخة Electron السابقة

1. **قبل التحديث**، ومن النسخة القديمة، ادخل كمدير وصدّر نسخة JSON من الشريط الجانبي. احتفظ بها في مكان آمن منفصل، وتحقق من أن حجمها ومحتوياتها معقولان. JSON غير مشفّر. إذا أمكن، احتفظ أيضاً بنسخة من مجلد بيانات التطبيق القديم بالكامل. لا تحذف مشروعك أو النسخة القديمة الآن.
2. أغلق النسخة القديمة تماماً قبل فتح الجديدة. لا تشغّل النسختين معاً لأنهما قد تشتركان في تخزين المتصفح القديم.
3. شغّل النسخة الجديدة على **نفس حساب Windows والجهاز**، وأنشئ عبارة التشفير. إذا عثر التطبيق على مفاتيح تخزين النسخة القديمة في ملفه الشخصي، يعرض سؤالاً واضحاً لنقلها. اختر الموافقة لنسخها إلى القاعدة المشفّرة في معاملة واحدة. لا تُحذف البيانات القديمة تلقائياً، ويُرفض النقل التلقائي إذا كانت قاعدة البيانات المشفّرة تحتوي بالفعل على مجموعات عيادة محفوظة.
4. ادخل بكلمات المرور القديمة المنقولة، وافحص المرضى والزيارات والخطط والتقارير والإعدادات، ثم احفظ نسخة احتياطية مشفّرة من الإعدادات. النسخة القديمة من `localStorage` والتصديرات السابقة **تظل غير مشفّرة**.
5. إذا أجّلت النقل والقاعدة لا تزال خالية، ستجد **نقل بيانات النسخة القديمة** في الإعدادات. إذا لم تظهر البيانات أو لم يُعثر على التخزين القديم، فلا تفترض أنها حُذفت: عد للنسخة القديمة وصدّر JSON، ثم من النسخة الجديدة ادخل كمدير واختر **استعادة نسخة (JSON)**. راجع البيانات بعدها؛ نسخة JSON لا تشمل كلمات مرور الأدوار. قد يختلف الوصول إلى التخزين القديم إذا تغيّر اسم التطبيق أو حساب Windows أو موقع ملفه الشخصي.
6. بعد التحقق والحصول على نسخة مشفّرة، يوجد في الإعدادات خيار لإزالة مفاتيح أوراس القديمة من `localStorage` بعد تأكيدين صريحين. هذه الإزالة **ليست محواً آمناً**؛ قد تبقى آثار داخل ملفات تخزين Chromium أو في نسخ الجهاز وتصديراته. عالج النسخ القديمة وفق سياسة خصوصية العيادة، واستخدم تشفير القرص الكامل وصلاحيات Windows المناسبة.

## أسعار الصرف والخصومات

- ادخل بحساب المدير وافتح **الإعدادات ← سعر الصرف وأسعار الإجراءات**. أدخل ما يقابل **دولاراً أمريكياً واحداً بالجنيه السوداني**، ثم اكتب السعر الأساسي بالدولار لكل إجراء تريد ربطه بالصرف، واضغط **حفظ سعر الصرف والأسعار**. يُدخل سعر الصرف يدوياً ولا يجلبه البرنامج من الإنترنت. يعرض الجدول القيمة المحسوبة بالجنيه ويقرّب التحويل إلى منزلتين عشريتين.
- السعر بالدولار الفارغ يعني أن الإجراء غير مربوط بالصرف: يبقى سعره الحالي بالجنيه ويمكن تعديله يدوياً من الجدول. إدخال صفر بالدولار يعني سعراً مجانياً، وليس إلغاء الربط. لإلغاء الربط امسح سعر الدولار؛ يبقى السعر المعروض بالجنيه قابلاً للتعديل بعد الحفظ. لا تُطبّق التعديلات حتى تضغط زر الحفظ.
- يطبّق سعر الصرف الجديد على **أسعار الإجراءات للزيارات الجديدة**، ولا يعيد تسعير الزيارات المسجّلة. تحتفظ الزيارة بسعر الإجراء عند إضافته؛ إذا عدّلت الزيارة بنفسك أو اخترت إجراءً آخر فقد تتغير فاتورتها وفق ما أدخلته في نموذج التعديل.
- في نموذج تسجيل أو تعديل الزيارة يمكن اختيار خصم إضافي **كمبلغ أو كنسبة مئوية** على مجموع أسعار الإجراءات في الزيارة. يحسب النظام الإجمالي بعد الخصم، ويتحقق أن الخصم لا يتجاوز الإجمالي أو 100%، وأن المدفوع لا يتجاوز المبلغ بعد الخصم، ثم يحسب المتبقي. تُقرّب مبالغ الفاتورة والخصم والمدفوع والمتبقي إلى منزلتين عشريتين.
- يظهر للمدير **مؤشر المبالغ المخفّضة المسجّلة** في لوحة النظرة العامة لجميع الفترات، وفي التقارير حسب الفترة المختارة. يجمع الخصم الإضافي وأي تخفيض يدوي في سعر بند الزيارة مقارنةً بسعره المحفوظ عند اختيار الإجراء. لا تُقابل زيادة سعر بند بتخفيض بند آخر. تُستبعد المواعيد المحجوزة والزيارات الملغاة، وتُوزّع الخصومات الإضافية بالتناسب على الإجراءات في تقارير إيرادات الخدمات.
- المؤشر **ليس** دين المرضى أو فرق النقد في الخزنة، ولا يثبت فقدان أموال أو يكشف الخصومات التي لم تُسجّل. الزيارات القديمة التي لم يُحفظ سعرها الأصلي لا تُنسب إليها خصومات بأثر رجعي؛ عند تعديل إحداها يُستخدم سعرها المحفوظ كنقطة بداية دون افتراض خصم سابق. يتغير المؤشر عند تعديل الزيارة أو حذفها، ولا يوجد سجل تدقيق مستقل.
- يُحفظ سعر الصرف وأسعار الدولار مع قاعدة البيانات المشفّرة ونسخ JSON الحديثة. قد لا تحتوي نسخة JSON قديمة أو جزئية على إعداد سعر الصرف؛ بعد استعادتها راجع الأسعار والإعداد قبل استخدامها. ملفات JSON المصدّرة غير مشفّرة.

## النسخ الاحتياطي والاستعادة

- من الإعدادات كمدير، اختر **حفظ نسخة احتياطية مشفّرة**. يُنسخ ملف قاعدة البيانات المحفوظة إلى ملف `.orasdb` مشفّر بعبارة التشفير نفسها، ويشمل السجلات والإعدادات وكلمات مرور الأدوار والنسخ التلقائية الداخلية. احتفظ بنسخ خارج الجهاز وافحص إمكانية استعادتها دورياً. إذا كانت هناك تغييرات غير محفوظة، عالج مشكلة الحفظ أو صدّر JSON قبل إنشاء النسخة المشفّرة.
- لاستعادة نسخة `.orasdb` كاملة: أغلق التطبيق تماماً، واذهب إلى `%APPDATA%\oras-dental-clinic\`. انقل مجلد `clinic-data` الحالي كاملاً إلى مكان آمن باسم مختلف للاحتفاظ بقاعدة البيانات والمفتاح المحمي وأي ملفات أخرى. أنشئ مجلداً جديداً اسمه `clinic-data` وانسخ إليه النسخة الاحتياطية باسم `oras-dental.sqlite3`. على حساب Windows والجهاز نفسيهما، يمكنك نسخ `oras-dental-key.dpapi` من المجلد القديم بعد نسخ قاعدة البيانات؛ سيعمل تلقائياً إذا كانت العبارة مطابقة. وإلا أدخل عبارة النسخة الأصلية مرة واحدة عند تشغيل التطبيق لإعادة تفعيل الفتح التلقائي. تحقق من البيانات ولا تحذف المجلد القديم قبل التأكد. هذه الاستعادة تستبدل القاعدة كلها، بما فيها كلمات مرور الأدوار؛ وهي إجراء يدوي حالياً.
- خيار **حفظ نسخة احتياطية (JSON)** وتصديرات Excel وPDF وملفات الطباعة **غير مشفّرة** وقد تحتوي على بيانات حساسة. احفظها في مكان محمي، وتحقق من المستلم قبل المشاركة. JSON يشمل مجموعات البيانات وملاحظات التقارير ولا يشمل كلمات مرور الأدوار.
- داخل القاعدة توجد نسخة تلقائية عند حفظ السجلات الأساسية ونقطة تراجع قبل الاستعادة، لكنها على الجهاز نفسه وليست بديلاً عن نسخة خارجية. استيراد JSON أو Excel يستبدل المجموعات الموجودة في الملف فقط، ويمكن التراجع من الإعدادات إن كانت نقطة التراجع متاحة.
- عند فشل الحفظ أو ظهور تعارض، لا تغلق الصفحة؛ احتفظ بالتغييرات وصدّر JSON في مكان آمن إذا لزم الأمر. لا يُستبدل ملف قاعدة البيانات تلقائياً عند كلمة مرور خاطئة أو فشل قراءة.

## حدود يجب معرفتها

- الفتح التلقائي يعني أن من يستطيع استخدام حساب Windows نفسه أو تشغيل برمجيات باسمه قد يتمكن من فتح القاعدة؛ ليست حماية مستقلة بكلمة مرور عند كل تشغيل. تشفير قاعدة البيانات لا يحمي البيانات أثناء فتح التطبيق، ولا يمنع من يتحكم بالجهاز أو بحساب Windows أو بالتطبيق من الوصول إليها. قد توجد بيانات في الذاكرة أو ملف ترحيل Windows أو ذاكرة المتصفح المؤقتة أو قوائم الطباعة أو نسخ احتياطية أو صادرات غير مشفّرة. تُعطّل النماذج الإكمال التلقائي والتدقيق الإملائي في نسخة Electron كإجراء احترازي، دون ضمان إزالة الآثار القديمة. استخدم حساب Windows محمياً، وأقفل الجهاز، وفعّل تشفير القرص الكامل، وحدّث النظام، وحدّد من يستطيع استخدامه.
- وضع المتصفح المباشر يظل للتجربة والاختبارات فقط ويستخدم `localStorage` **غير المشفّر**، بما في ذلك نسخ الاستعادة التلقائية. حماية قاعدة البيانات متاحة عند تشغيل مشروع Electron الموحّد، لا عند فتح `index.html` وحده. إذا فشل جسر Electron، يمنع التطبيق الدخول بدلاً من الرجوع بصمت إلى تخزين غير مشفّر.
- مبلغ الزيارة المدفوع تراكمي ومرتبط بتاريخ الزيارة، وليس هناك سجل بتاريخ كل دفعة؛ التقارير لا تمثل بدقة التحصيل في تواريخ لاحقة. لا تُخصم تكاليف المعامل من صافي الدخل إلا إذا أُدخلت أيضاً في المصروفات.
- لا توجد مزامنة على الشبكة أو سجل تدقيق أو صلاحيات خادمية أو اعتماد أمني؛ راجع المتطلبات القانونية وحماية الخصوصية للعيادة قبل اعتماد النظام إنتاجياً.

## الاختبارات للمطورين

```sh
npm ci --ignore-scripts
npm test
```

تشمل اختبارات قاعدة البيانات فحص التشفير وكلمات المرور والمعاملات والنقل والنسخ الاحتياطي، واختبارات للواجهة والحفظ والتقارير والاستعادة. اختبارات Electron للواجهة هنا تستخدم جسراً تجريبياً مع قاعدة مشفّرة حقيقية، وليست بديلاً عن تشغيل التطبيق وفحص البناء النهائي على Windows. على Linux تستخدم Playwright وChromium المضمّن؛ على Windows يمكن تعيين `CHROME_PATH` إلى متصفح Chrome/Chromium مثبت قبل تشغيل الاختبارات. لا تغني الاختبارات عن المراجعة الأمنية وتجربة الاستعادة الفعلية على جهاز العيادة.
